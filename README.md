# 💯 100LOG

> 최근 RP의 중요한 사실을 기억하고, 설정 오류가 있는 AI 답변은 사용자에게 보여주기 전에 검사하는 SillyTavern 확장입니다.

현재 버전: `v1.9.31`

### Silly Relay 답장 복구 연동

- Silly Relay 1.0.8과 함께 쓰면 100LOG가 실제로 재작성한 캐릭터 답장도 원래 답장과 묶어서 복구합니다. 또또 1.13.18이 먼저 수정한 답장에 이어서 검수·재작성해도 지원합니다.
- JEV 판정·기억 수집·번역은 기존대로 실행합니다. 이 보조 결과를 캐릭터 답장으로 복구하거나 릴레이 보관 자리에 넣지는 않습니다.
- 재작성에 실패하면 받아둔 정상 답장을 유지하며, 중단·채팅 변경·수동 편집 뒤 늦게 온 수정본은 적용하지 않습니다. 릴레이를 쓰지 않으면 기존 방식대로 동작합니다.
- **실리태번 확장 관리에서 100LOG 1.9.31과 Silly Relay 1.0.8을 업데이트하고, 진행 중인 답장 처리가 끝나면 새로고침합니다.** 릴레이 서버 플러그인은 1.0.2 그대로이며 이번 연동에 서버 업데이트나 재시작은 필요 없습니다.
- 서버가 이미 접수한 답장 요청을 보관하는 기능입니다. 브라우저 종료 후 아직 시작하지 않은 다음 검수·재작성 단계를 대신 실행하지는 않습니다.

### 기억 개수 표시 · 설정 순서 정리

- 마지막 검수 당시 개수와 밀어내기 직후 개수를 현재 규칙 개수와 구분해 표시합니다. 기존에 저장된 밀어내기 기록도 같은 문구로 표시합니다.
- 설정에서 ‘수집 후 규칙 자동 청소’를 ‘오래된 기억 자동 밀어내기’ 위로 옮겼습니다.

### 오래된 기억 밀어내기 · JEV 선택 사용

- 설정에 ‘오래된 기억 자동 밀어내기’와 유지할 개수(1~40개)를 추가했습니다. 기본값은 꺼짐이며, 켜거나 개수를 줄이면 즉시 적용하고 이후 수집에도 적용합니다.
- 수집 순서가 오래된 자동 기억부터 현재 목록에서 빼고 보관 기록에 남깁니다. 직접 저장·잠금한 기억은 유지합니다. 잠그지 않은 약속·비밀도 밀려날 수 있습니다. 개수가 보호된 기억으로 차면 새 기억을 저장하지 않습니다.
- JEV 답변 검수를 선택 사항으로 분리했습니다. 끄면 JEV 키 없이도 기억 수집·정리·주입을 사용하며 답변은 정상적으로 스트리밍합니다. 수집·AI 청소용 AI 연결은 여전히 필요합니다.
- 기존에 100LOG를 켜고 JEV 키를 저장해둔 사용자는 검수를 유지합니다. 키를 삭제해도 기억 기능은 끄지 않습니다.
- 수집 강도는 다음 수집·누락 재확인에 적용됩니다. ‘지금 청소’는 재수집이 아니며, 기존 목록을 바뀐 강도로 다시 구성하려면 ‘최근 100개 재수집’을 사용합니다.

### 자동 청소 개선 · 수동 청소

- 새 대화나 원문 수정이 있으면 저장된 기억이 같아도 자동 청소를 다시 판단합니다.
- 이번 수집에서 40개 한도로 빠진 기억은 청소 후 원문을 확인하고 저장을 다시 시도합니다.
- 설정의 ‘지금 청소’는 자동 청소 사용 여부와 시작 개수에 관계없이 다시 검사합니다. 중단할 수 있으며 직접 저장·잠금한 기억은 보호합니다.
- AI의 원래 제안 수, 실제 정리 수, 코드에서 제외한 이유를 구분해 표시합니다. 정리할 대상이 없으면 기억을 강제로 지우지 않습니다.
- 업데이트 전에 한도로 제외됐던 기억은 수동 청소 후 ‘누락 재확인’으로 다시 수집할 수 있습니다.

### 검수 대기 화면 정리

- 채팅 화면의 검수 대기 문구와 큰 빈 답변칸을 없앴습니다. 검수 중인 답변은 공간을 차지하지 않고, 검수가 끝나면 표시됩니다.

### 이번 업데이트: 실리태번의 원래 답변을 받아 검수

- **사실 주입 → 실리태번 정상 생성 → 받은 답변 검수 → 충돌이 있을 때만 재작성** 순서로 동작합니다.
- 최초 생성을 중단하고 숨은 초안을 별도로 만들던 방식을 제거했습니다. 사용자의 프리셋·로어북·다른 확장 주입은 원래 생성 과정에 그대로 참여합니다.
- 통과한 답변의 원문·모델·시간·스와이프 정보를 그대로 유지합니다. 수정이 필요할 때만 같은 메시지의 현재 답변을 교체하고, 실리태번이 표시·저장을 마칩니다.
- 스트리밍은 원래대로 수신하되 해당 답변 본문·추론·미디어를 검수 완료까지 가립니다. 비스트리밍은 화면 표시 전의 답변 수신 이벤트를 기다립니다.
- 중단·채팅 변경·메시지 편집 뒤 늦게 도착한 수정 결과는 반영하지 않습니다. 실리태번이 이미 받은 원래 답변이나 부분 응답을 임의로 삭제하지 않습니다.
- **429die v1.9.12**와 함께 업데이트해 주세요. 첫 답변의 오류는 기존 본채팅 재시도가, 검수·재작성의 오류는 단계별 연동 재시도가 맡습니다. v1.9.11의 연동 API도 호환됩니다.
- 검수 재시도는 같은 답변을 사용하며 성공한 배치는 반복하지 않습니다. 429die의 재시도 횟수(0=무제한)·대기 배지·중단을 따르고, JEV 요청마다 60초 응답 제한을 적용합니다.
- 재시도를 소진하면 받은 답변을 보존하고 검수 미완료로 기록합니다. 기억 수집·번역·임베딩은 답변 재시도 연동 대상이 아닙니다.

### 나중에 알게 된 인물의 지식 갱신 보강

- 새 대화를 수집할 때 기존 기억과 요약 이월 기억의 인물별 지식을 다시 대조하도록 지시를 보강했습니다. 근거 없이 모두 ‘알고 있음’으로 바꾸지는 않습니다.
- 같은 기억에 여러 인물의 지식 갱신이 따로 제안되어도 뒤쪽 제안을 버리지 않습니다.
- 사실 내용이 같은 갱신은 지식만 반영합니다. 다른 인물의 기록, 원래 출처, 이월 기간, 표시 순서를 유지합니다. 수동 지정한 지식과 잠근 기억은 보호합니다.
- 이미 지나간 대화에서 빠진 지식은 ‘누락 재확인’으로 다시 확인할 수 있습니다. 새 버전 설치만으로 모든 기억을 다시 분석하지는 않습니다.

### 최근 수집한 기억부터 표시

- 현재 규칙을 저장된 순서의 역순으로 표시합니다. 새로 수집하거나 직접 저장한 기억이 위에 나오고, 기존 기억의 지식·진행 상황만 수정해도 순서는 바뀌지 않습니다.

### 기억 수집을 백그라운드로 분리

- 설정한 주기마다 마지막 수집 위치부터 뒤에서 이어서 정리합니다. 수집 중에도 저장된 기억으로 답변 생성·JEV 검수를 계속합니다.
- 답변 생성 시작 시 기억을 복사해 검수 기준을 고정합니다. 수집이 끝나며 추가·변경된 기억은 다음 답변부터 사용합니다.
- 수집 도중 쌓인 새 대화는 다음 수집에서 이어서 처리합니다. 같은 수집을 중복 실행하지 않습니다.
- 별도 연결 프로필 또는 현재 메인 채팅 완성 API를 독립 요청으로 사용합니다. 전송 버튼과 메인 토큰 설정을 변경하지 않으며, 답변 생성 취소와 수집 중단도 분리됩니다.
- 구형 실리태번 등 독립 요청 기능이 없거나 메인 텍스트 완성 API를 쓰는 경우에는 기존 호환 경로를 유지합니다. 이 경로의 수집 중에는 답변을 실리태번 기본 생성으로 진행합니다. 완전한 병행 처리를 원하면 정리용 연결 프로필을 선택해 주세요.
- 같은 API를 동시에 사용하면 제공업체의 처리 속도·요청 제한에 영향을 받을 수 있습니다. 앱을 닫은 뒤에도 실행되는 기능은 아닙니다.

### 사용자 메시지 전송 전 수집 대기 제거

- 보내기를 눌렀을 때, 메시지가 채팅에 등록되기 전에 기억 수집을 기다리거나 새로 시작하던 처리를 제거했습니다. 대기 중인 자동 수집은 답변 생성 뒤에 진행합니다.
- 전송 준비 중 기억 정리 오류가 나도 사용자 메시지 전송을 중단하지 않습니다.
- 별도 정리 프로필 없이 메인 API로 수집·번역할 때 출력 길이를 6,000토큰으로 덮어쓰던 요청 옵션을 제거했습니다. 실리태번에 설정된 출력 길이를 사용합니다. 별도 연결 프로필의 보조 작업 요청 한도는 기존대로 유지합니다.

### 검수 오류로 답변이 사라지는 문제 수정

- JEV 오류·토큰 한도 초과·60초 대기 초과가 발생하면 검수를 건너뛰고 받아둔 답변을 표시합니다. 검수 결과에는 ‘미완료’로 구분합니다.
- 재작성 요청이 실패하면 처음 받은 답변을 유지합니다. 중단하거나 채팅이 바뀌면 늦게 온 수정 결과는 반영하지 않습니다.
- 독립 요청을 지원하는 수집·번역 중에도 100LOG 답변 검수를 진행합니다. 기존 호환 경로에서는 보내기를 막지 않고 실리태번 기본 생성으로 진행합니다.
- 긴 공통 검수 지시를 한 번만 보내 요청 크기를 줄였습니다. 답변 본문과 검수할 기억은 자르지 않습니다.
- 업데이트된 모듈을 새 주소로 불러오도록 변경했습니다. 업데이트 후 새로고침해 주세요.

### 충돌이 남아도 재작성 답변 표시

- 충돌을 발견하면 한 번 재작성하고 다시 검사합니다.
- 재검수에서 충돌이 남아도 재작성한 답변을 표시합니다. 추가 자동 재작성은 하지 않습니다.
- 남은 충돌은 100LOG 검수 결과에만 표시하며 별도 토스트는 띄우지 않습니다.
- 생성 취소나 채팅 변경 시에는 늦게 온 수정 결과를 반영하지 않습니다. 메인 AI 답변 자체가 없으면 검수를 시작하지 않습니다.

### 저장된 기억을 기준으로 답변 검수

- 정리 AI는 기존처럼 원문을 읽어 기억과 인물별 지식을 수집·갱신합니다.
- JEV는 저장된 기억과 새 답변을 비교합니다. 검수용 원문·최근 대화·근거 인용 전달과 원문 우선 판단을 제거했습니다.
- 기억에 없는 새 사건, 약속 이행·취소, 새로 정보를 배우는 자연스러운 진행은 모순으로 취급하지 않도록 지시합니다.
- 저장된 기억 자체가 틀리면 검수도 영향을 받을 수 있으므로 해당 기억을 수정해 주세요. 모델의 판단 정확도를 보장하는 기능은 아닙니다.


수집할 때 공개된 사실과 숨은 의도처럼 아는 사람이 다른 내용은 별도 기억으로 구분하도록 정리 AI에 지시합니다. 기존 기억을 새로 전달받은 인물은 내용·원래 출처를 유지한 채 지식만 갱신할 수 있습니다. 이때 새 원문의 인용 근거가 필요하며, 다른 인물의 지식과 직접 지정한 지식은 유지합니다. AI 판단이므로 분리나 지식 판정이 항상 정확한 것은 아닙니다.

### 이름이 달라도 같은 인물로 연결하기

설정의 **인물 이름·별칭 연결**에서 영어 이름, 한국어 표기, 별명을 대표 이름에 연결할 수 있어요. 정리 AI가 연결 후보를 제안하기도 하지만, 사용자가 승인하기 전에는 합치지 않아요. 승인한 연결은 같은 캐릭터의 채팅끼리 공유하며 수집·지식 표시·답변 생성·검수에 반영해요. 이름만 비슷한 다른 인물은 연결하지 마세요.

기존 지식 상태가 충돌하면 임의로 ‘알고 있음’을 고르지 않고 **확인 안 됨**으로 표시해요. 직접 지정한 지식은 우선하며, 직접 지정한 내용끼리도 충돌하면 확인이 필요해요. 연결 해제는 원래 저장된 이름을 다시 구분해요. 연결 중 직접 저장하거나 새로 수집한 지식을 과거 상태로 되돌리는 기능은 아니에요.

### 이후 대화에서 확인된 근거

정리 AI가 뒤의 대화에서 같은 사실을 뒷받침하는 장면을 찾으면 기존 기억에 **추가 근거**를 붙여요. 기억 아래에서 펼쳐 볼 수 있으며 최대 4개를 보관해요. 근거는 수집 AI의 참고 정보와 사용자가 확인하는 기록으로 유지해요. 답변 생성용 기억 주입과 JEV 검수에는 근거 인용 대신 정리된 기억을 전달해요. 단순히 여러 번 언급됐다고 참으로 확정하지 않으며, 인용 일치는 코드로 확인하고 의미 판단은 AI가 맡아요.

근거가 추가돼도 기억의 원래 출처·정렬·보관 기간은 그대로예요. 현재 채팅에서 숨겨지거나 수정된 원문의 추가 근거는 사용하지 않아요. 직접 저장하거나 잠근 기억은 자동 변경하지 않아요. 이전 기억의 근거를 보충하려면 **누락 재확인**을 누르세요. 별도의 JEV 수집 검증이나 추가 정기 호출은 없어요.

### 잘못 수집된 기억을 다시 모으지 않기

현재 규칙의 **⋯ → 삭제**에서 이유를 선택해요.

- **지금 필요 없음 · 삭제**: 일반 삭제예요. 이후 다시 수집될 수 있어요.
- **잘못 수집됨 · 재수집 제외**: 같은 원문의 같은 내용을 다시 모으지 않도록 기록해요. 원문 출처가 있는 기억에 사용할 수 있어요.

자동 수집·누락 재확인·최근 100개 재수집에 모두 적용해요. 같은 내용과 출처는 코드로 걸러내고, 표현을 바꾼 제안은 정리 AI의 동일 내용 판정을 함께 사용해요. 의미 판정은 완벽하지 않아요. 같은 메시지의 다른 사실이나 이후 새 메시지에서 실제로 일어난 사건까지 막지는 않아요.

설정의 **잘못 수집된 기억 · 재수집 제외**에서 해제할 수 있어요. 해제만으로 기억이 복원되지는 않으며, 필요하면 누락 재확인을 누르세요. 제외 기록은 캐릭터별 최대 200개이고 원문이 해당 채팅의 최근 100개 범위 밖으로 나가면 정리돼요. 오류 진단에는 이 내용이나 이름을 기록하지 않아요.


검수 규칙 화면의 ‘누락 재확인’을 누르면 저장된 기억을 유지하면서 최근 100개 공개 대화를 다시 읽고 빠진 기억과 지식 변화를 보충합니다. 일반 수집 뒤 자동으로 실행하지 않습니다. 버튼을 누를 때 정리 AI 호출이 발생하며, 대화 분량에 따라 여러 묶음으로 나누어 확인합니다. 자동 수집 진행 위치는 바꾸지 않으며 별도 자동 청소도 하지 않습니다. 실패·중단한 묶음은 반영하지 않고, 이미 완료된 묶음은 유지합니다. 다시 누르면 현재 기억과 비교해 재확인합니다. JEV는 수집이 아닌 답변 검수를 맡습니다.

인물별 지식 편집은 간결한 목록형입니다. 수집된 인물 이름과 상태를 한 줄씩 표시하고, 여러 명을 수정한 뒤 한 번에 저장할 수 있어요. 판단 근거는 목록 아래에서 펼쳐 확인·수정합니다. 제외된 기억의 직접 저장 화면에도 같은 목록형을 사용하며, 저장 후 보던 위치를 유지합니다.

## 이번 버전에서 달라진 점

- 지식 편집·저장과 제외 기억 저장 후에도 보던 스크롤 위치를 유지합니다. 저장 중 목록을 다시 그리면서 위로 튀던 동작을 보정했습니다.
- 기존 기억에서도 여러 인물의 지식 상태를 선택한 뒤 ‘지식 한 번에 저장’을 누를 수 있습니다. 기존 상태를 미리 표시하며, 변경하지 않은 인물의 원문 근거는 유지합니다.
- 인물별 × 또는 미지정을 선택하면 저장할 때 해당 지식 기록을 지웁니다. 편집창은 저장 후에도 열린 상태로 유지됩니다.

- 제외된 기억을 직접 저장하기 전에 인물별 지식을 선택할 수 있습니다. 저장하면 제외 목록에서 즉시 사라집니다.
- 기존 기억의 인물별 지식 편집과 제외 기억의 직접 저장에서 수집된 인물 이름을 선택할 수 있습니다. 이름을 제안하는 기능이며, 알고 있음·모름을 자동 지정하지는 않습니다.
- 현재 규칙은 최근 수집·저장한 기억부터 표시합니다. 원문 메시지 번호나 채팅별로 재정렬하지 않으며, 인물별 지식만 수정해도 표시 순서는 유지합니다.

- 설정에 **집중해서 수집할 항목**을 추가했습니다. 약속·관계·비밀·취향·선물·사건·부탁 중 여러 항목을 선택하거나 추가 기준을 직접 적을 수 있습니다.
- 수집 기준은 캐릭터별로 저장되어 같은 캐릭터의 채팅에서 공유하며, 다음 수집부터 적용됩니다. 선택하지 않은 항목을 수집 대상에서 제외하지는 않습니다.
- 설정에서 **최근 수집 중 제외된 제안과 이유**를 확인할 수 있습니다. 이 채팅의 최근 수집 1회만 보관하고 최대 64개를 표시합니다. AI가 아예 추출하지 않은 내용과 자동 청소는 포함하지 않습니다.
- 제외된 추가·갱신 제안은 내용을 확인·수정한 뒤 새 수동 규칙으로 저장할 수 있습니다. 기존 규칙은 덮어쓰지 않으며, 인물별 지식을 선택해 함께 저장할 수 있습니다. 잠금과 40개 한도는 유지됩니다.
- 수집·지식 정리·청소는 정리 AI가, 새 답변·재작성 검수는 JEV가 맡는 방식은 그대로입니다. 기억 수정용 JEV 호출을 추가하지 않았습니다.

## 100LOG가 필요한 이유

RP가 길어지면 AI가 다음과 같은 실수를 할 수 있습니다.

- 방금 한 약속을 잊음
- 아직 실행하지 않은 계획을 이미 끝난 일처럼 말함
- 한 인물만 아는 비밀을 다른 인물도 알고 있음
- 취소된 약속을 계속 진행함
- 사용자가 정정한 내용을 다시 틀림
- 앞 장면과 맞지 않는 행동이나 반응을 보임

100LOG는 최근 대화에서 이런 정보를 `검수 규칙`으로 정리하고, 새 답변이 규칙과 충돌하는지 JEV로 확인합니다.

장기 세계관 전체를 저장하는 확장은 아닙니다. 오래된 설정과 줄거리는 로어북·요약 확장에 맡기고, 100LOG는 현재 RP와 가까운 최근 흐름을 관리합니다.

## 작동 방식

### 1. 규칙 수집

1. 최근 100개의 보이는 사용자·AI 메시지를 읽습니다.
2. 규칙 정리용 AI가 약속·비밀·오해·정정사항처럼 계속 기억할 내용을 찾습니다.
3. 정리 AI가 인물별로 무엇을 알고 있는지와 그 근거도 함께 정리합니다.
4. 코드가 원문 인용·형식·중복·잠금 조건을 검사한 뒤 저장합니다. 이 단계에서는 JEV를 호출하지 않습니다.

### 2. 기억 주입과 선택적 답변 검수

JEV 검수를 끄면 저장된 사실만 주입하고, 답변은 실리태번의 원래 방식으로 표시합니다. 아래 과정은 JEV 답변 검수를 켠 경우에만 적용됩니다.

1. 저장된 사실을 깊이 0에 주입하고, 실리태번이 원래 설정으로 메인 AI 답변을 생성합니다.
2. 100LOG가 받은 답변을 표시 전에 잠시 보류하고, JEV가 답변과 현재 규칙의 내용·인물별 지식·약속 진행 상태를 비교합니다. 원문을 다시 해석해 저장된 기억을 뒤집지 않습니다.
3. 문제가 없으면 받은 답변을 그대로 표시합니다.
4. 문제가 있으면 충돌한 부분을 알려 메인 AI에 한 번 재작성을 요청합니다.
5. 수정 답변도 다시 검사한 뒤 표시합니다. 충돌이 남으면 검수 결과에 남기며, 추가 재작성은 하지 않습니다.

일반 답변·재생성·스와이프 모두 같은 검수를 거칩니다.

## 어떤 내용을 기억하나요?

### 수집하는 내용

- 아직 실행되지 않은 약속·계획·목표
- 날짜·시간·장소가 정해진 일정
- 해결되지 않은 사건·질문·갈등
- 누가 무엇을 알고 있거나 아직 모르는지
- 비밀·거짓말·오해·숨긴 사실
- 사용자가 직접 정정한 내용
- 다음 답변의 인과관계에 필요한 최근 사건
- 현재도 영향을 주는 관계 변화

### 수집하지 않는 내용

- 평범한 대사와 반응 전체
- 장기 세계관과 캐릭터 설정 전체
- 현재 날짜·시각·날씨·장소
- 현재 복장·자세·위치·소지품
- 시스템 메시지와 숨김 메시지의 본문

현재 장면의 날짜·장소·복장·자세 같은 정보는 또또SFW가 담당합니다.

## 약속은 어떻게 처리하나요?

약속의 목적을 실제로 이뤘는지 확인합니다. 단순 방문 약속은 방문이 확인되면 완료할 수 있지만, 특정 활동을 끝내기로 한 약속은 도착만으로 완료하지 않습니다.

원문에 `약속대로`, `약속을 지켰다`라는 말이 없어도 참여 인물·행동·목적이 명확하면 판단합니다. 시작만 확인되면 진행 중으로 갱신하고, 완료·취소가 확인되면 지난 규칙으로 옮깁니다. 시간이 지났거나 언급이 사라졌다는 이유만으로 종료하지 않습니다. 이 판단은 정리 AI가 하며, 원문 인용과 작업 조건은 코드로 확인합니다.

같은 약속의 진행 갱신은 동일한 항목에 이어 붙이며, 최근 진행 이력 12개를 보관합니다. 잘못된 갱신은 기존의 `최근 갱신 취소`로 되돌릴 수 있습니다. 자동 판정이 항상 정확한 것은 아닙니다.

약속 이행이 여러 메시지에 걸쳐 이어지는 경우를 놓치지 않도록 새 분석 구간 바로 앞의 메시지를 최대 8개까지 함께 참고합니다.

## 규칙의 종류

### 검수 규칙

현재 답변 검사에 사용하는 활성 규칙입니다.

- 메인 AI 생성 전에 필요한 규칙을 주입합니다.
- JEV가 새 답변과 비교합니다.
- 최대 40개까지 활성화됩니다.
- 수정·잠시 끄기·자동 변경 잠금·삭제가 가능합니다.

### 지난 규칙

완료·취소·갱신되어 더 이상 사용하지 않는 규칙의 기록입니다.

- 메인 AI에게 주입하지 않습니다.
- JEV 답변 검수에도 사용하지 않습니다.
- 활성 규칙 40개 한도에 포함되지 않습니다.
- 잘못 종료된 규칙은 다시 복구할 수 있습니다.
- 종료된 시점이 최근 100개 범위 밖으로 나가면 자동 삭제됩니다.

### 요약 이월

요약 확장이 많은 원문 메시지를 하이드했을 때도 잠시 유지해야 하는 중요 규칙입니다.

- 미해결 약속·계획·비밀·지식 차이·오해·정정사항 등을 유지합니다.
- 최초 이월 뒤 새 메시지 100개 동안 검수에 사용합니다.
- 중간에 다시 요약해도 100개 계산이 초기화되지 않습니다.
- 같은 규칙을 요약할 때마다 복사하지 않습니다.
- 완료·취소·갱신되면 즉시 지난 규칙으로 이동합니다.
- 100개가 지나도록 미해결이어도 장기 요약에 맡기고 자동 삭제합니다.
- 화면에서 `요약 이월 70/100`처럼 진행도를 확인할 수 있습니다.

## 요약 확장과 함께 사용할 때

100LOG는 하이드 규모에 따라 다르게 처리합니다.

### 분석된 메시지 8개 이상을 한꺼번에 하이드

`요약 압축`으로 자동 인식합니다.

- 중요한 미해결 규칙은 요약 이월로 유지합니다.
- 완료된 짧은 사건과 일반 장면 규칙은 삭제합니다.
- 여러 하이드 이벤트를 모아 한 번만 처리합니다.
- 최근 작업에서 하이드·이월·정리 개수를 확인할 수 있습니다.

### 메시지 8개 미만을 하이드하거나 수정

일반적인 대화 수정으로 처리합니다.

- 해당 메시지에서 나온 규칙을 되돌립니다.
- 영향을 받은 이후 구간을 다시 분석합니다.
- 관련 없는 이전 규칙은 유지합니다.

업데이트 전에 이미 하이드되어 삭제된 규칙은 자동으로 복구할 수 없습니다.

## 처음 사용하기

1. `100LOG → 설정`을 엽니다.
2. `정리용 연결 프로필`을 선택합니다.
3. 답변 검수도 원하면 JEV API 키를 입력하고 `연결 확인` 후 `JEV로 받은 답변 검수`를 켭니다. 기억 기능만 사용하면 생략합니다.
4. 상단의 `사용`을 켭니다.
5. 평소처럼 RP를 진행합니다.

규칙 정리용 프로필을 비워두면 현재 메인 API를 사용합니다. 메인 RP와 규칙 정리를 분리하고 싶다면 별도 연결 프로필을 선택하세요.

서버 플러그인은 필요하지 않습니다.

## 주요 설정

### 집중해서 수집할 항목

설정에서 여러 항목을 선택할 수 있습니다. 선택 항목은 작은 내용도 더 주의해서 수집하도록 정리 AI에 전달합니다. 추가 수집 기준도 선택 사항이며 입력하면 자동 저장됩니다. 아무것도 선택하거나 적지 않으면 기존 수집 방식을 유지합니다.

선택은 수집 우선순위를 알려주는 기능으로, 모든 항목이 반드시 저장된다는 보장은 아닙니다. 원문 근거·인물별 정보 전달·중복·저장 한도는 계속 검사합니다. 기존 기억을 다시 정리하려면 ‘최근 100개 재수집’을 사용하세요.

### 수집에서 제외된 항목

현재 채팅의 최근 수집에서 코드 검사로 빠진 제안과 실제 제외 이유를 설정에 표시합니다. 출처 인용 불일치, 중복, 변경 없음, 잠금, 한도 등을 구분합니다. 각 항목의 ‘인용 확인 · 직접 저장’을 열면 내용을 수정하고 인물별 지식을 선택해 수동 규칙으로 추가할 수 있습니다. 인물 이름은 수집된 기록과 최근 대화의 발화자에서 가져오며 직접 입력도 가능합니다. 미지정 인물은 지식 상태로 저장하지 않습니다. 저장한 항목은 제외 목록에서 빠집니다. 근거 인용이 원문과 일치하지 않을 수도 있으므로 내용을 직접 확인해 주세요.

완료·취소 제안은 여기서 새 사실로 저장하지 않습니다. 기존 규칙의 관리 메뉴에서 처리하세요. 최신 수집 내역만 채팅별로 보관하며 최대 64개를 표시합니다. ‘내역 지우기’는 제외 목록만 비우고 현재 기억은 삭제하지 않습니다. 이전 버전의 제외 이유는 복원할 수 없습니다. 이 목록은 오류 진단과 분리되어 있으며 오류 복사에 내용이 포함되지 않습니다.

### 규칙 수집 강도

- `세세하게`: 작은 결정·요청·거절·관계 변화까지 넓게 수집
- `균형`: RP 연속성에 필요한 내용을 적당히 수집하는 기본값
- `의미 중심`: 중요한 사건과 관계 변화 위주로 수집

명시적인 약속·일정·취소·정정·비밀·지식 차이는 강도와 관계없이 수집 대상입니다.

### 자동 규칙 갱신 주기

AI 답변이 몇 개 쌓일 때마다 새 대화를 분석할지 정합니다.

예를 들어 `5`로 설정하면 AI 답변 5개마다 규칙을 갱신합니다. 사용자 메시지는 주기 계산에 포함하지 않습니다.

### 자동 청소 시작 개수

활성 규칙이 설정한 개수 이상 쌓이면 정리용 AI가 중복·완료·충돌 후보를 찾습니다.

정리 AI의 제안을 원문 인용·대상 규칙·병합 조건에 맞는지 코드로 검사한 뒤 적용합니다. 청소에는 JEV를 호출하지 않습니다. 판단하기 어려운 충돌은 표시만 남깁니다. 직접 추가하거나 자동 변경 잠금한 규칙은 자동 청소가 변경하지 않습니다.

활성 규칙은 최대 40개이며, 지난 규칙은 이 한도에 포함되지 않습니다.

### 새 대화만 갱신

기존 규칙은 유지하고 아직 분석하지 않은 새 대화만 반영합니다.

### 최근 100개 처음부터 재수집

현재 채팅에서 자동으로 만든 규칙을 비우고 최근 100개를 처음부터 다시 분석합니다.

직접 추가하거나 자동 변경 잠금한 규칙은 유지됩니다. 같은 캐릭터의 다른 채팅에서 모은 규칙도 지우지 않습니다.

## 인물별 지식

각 규칙에는 인물별로 다음 상태를 기록할 수 있습니다.

- `알고 있음`: 직접 경험했거나 전달받아 사실 전체를 알고 있음
- `아직 모름`: 정보가 전달되지 않았거나 비밀로 유지되는 등 모르는 근거가 확인됨
- `확인 안 됨`: 알고 있는지도 모르는지도 확정할 수 없음. 이 상태만으로 메타게이밍 위반을 판정하지 않습니다.

인물 이름이 규칙에 등장했다는 이유만으로 `알고 있음`으로 처리하지 않습니다. 정리 AI가 원문에서 실제 정보 전달 경로를 판단합니다. JEV는 새 답변 검수에서 저장된 지식 표시를 기준으로 사용합니다. ‘확인 안 됨’이나 미지정 상태를 ‘모름’으로 취급하지 않으며, 답변 안에서 새로 정보를 배우는 전개는 허용하도록 지시합니다.

지식 상태는 현재 장면에 함께 있는지가 아니라 정보가 실제로 전달·노출·관찰되었는지를 기준으로 판단합니다. 대화·통신·기록·관찰·감시 등으로 내용을 접한 인물은 장면 밖에 있어도 `알고 있음`으로 처리하며, 근거가 불분명하면 임의로 `아직 모름`을 붙이지 않습니다.

이름·상태를 누르면 근거와 수정 칸이 열립니다. 상태·이름·근거를 수정하거나 `× 기록 삭제`로 해당 기록만 지울 수 있습니다. 직접 수정한 규칙은 자동 변경 잠금 상태가 됩니다. 이전 버전의 기록은 상태를 유지하되, 당시 근거가 저장되지 않았음을 표시합니다.

새 지식 기록은 정리 AI가 상태·근거 문장·설명을 정리합니다. 코드는 제시된 인용이 원문에 있는지 확인하며, 지식 상태의 의미를 별도 AI로 재검증하지 않습니다. ‘확인 안 됨’은 정리 AI가 근거만으로 상태를 확정하지 못했다는 뜻입니다. 공개된 사건을 안다는 것과 그 뒤의 숨은 의도를 안다는 것은 구분해서 기록합니다.

## 이번 답변에서 한 일

검수 규칙 화면 맨 위에 **현재 채팅의 마지막 검수 결과 1건**을 표시합니다. 수집 작업이 실행되어도 이 결과를 덮어쓰지 않습니다.

- `모순 없음`: 검수에서 명확한 충돌을 찾지 못했습니다.
- `재검수 후 표시`: 충돌을 발견해 한 번 재작성하고 재검수를 통과했습니다.
- `충돌 N개 남음`: 한 번 재작성한 답변을 표시했지만, 재검수에서 충돌이 남았습니다. 검수 결과를 펼치면 관련 기억을 볼 수 있습니다.
- `검수 미완료 · 받은 답변 표시`: JEV 오류·대기 초과 또는 재작성 실패로 받아둔 답변을 표시했습니다. 검수를 통과했다는 뜻은 아닙니다.
- `생성 실패`: 메인 AI에서 최초 답변을 받지 못했습니다.
- `표시·저장 오류`: 검수 후 표시나 저장이 실패했습니다. 이미 보이는 답변이 있을 수 있어 채팅을 확인해야 합니다.

결과를 누르면 관련 규칙과 실제로 보낸 수정 지시의 요지를 확인할 수 있습니다. 불확실한 판정 개수도 별도로 표시합니다. 본문 전체나 숨은 초안을 작업 내역에 저장하지 않으며, 결과 표시를 위한 추가 AI 호출은 없습니다.

이 검수 내역은 채팅별로 저장됩니다. 설정의 `마지막 오류`는 기존처럼 본문·규칙·인물명·키를 제외한 기술 진단만 기록하므로 서로 다릅니다.

- 표시 이름이 같아도 다른 캐릭터 카드의 규칙은 섞이지 않습니다.

따라서 같은 캐릭터의 여러 채팅은 하나의 이어지는 세계선으로 취급됩니다.

## API 사용량

정상 답변에서는 다음 요청이 실행됩니다.

- 실리태번의 원래 메인 AI 답변 생성 1회 (100LOG가 별도로 첫 답변을 생성하지 않음)
- JEV 답변 검수 1회 (검수를 켠 경우에만)

오류가 발견된 경우에만 다음 요청이 추가됩니다.

- 메인 AI 재작성 1회
- JEV 재검수 1회

규칙 갱신 시에는 설정한 주기에 맞춰 규칙 정리용 AI를 호출합니다. 자동 청소는 규칙이 설정한 개수 이상이고 이전 청소 뒤 기억이나 최근 대화가 바뀌면 추가로 실행합니다. 수동 청소는 버튼을 누르면 다시 요청합니다. 오래된 기억 밀어내기는 코드로 처리하므로 AI 요청을 추가하지 않습니다.

### 응답이 늦거나 오류가 날 때

- 아래 2회·60초 정책은 429die 연동이 꺼져 있을 때의 기본값입니다. 연동 중에는 429die 설정을 따르며 60초는 요청 한 번의 응답 제한입니다.
- JEV 요청이 30초 이상 걸리면 `JEV 응답이 늦어지고 있습니다.`라는 안내를 띄웁니다. 답변 검수는 재시도 시간을 포함해 한 단계당 최대 60초 기다린 뒤, 미완료로 기록하고 받아둔 답변을 표시합니다.
- JEV의 429·서버 오류·연결 실패·잘못된 응답은 최대 2회 자동 재시도합니다. 기본 대기 시간은 2초, 5초이며 서버가 더 긴 대기를 요청하면 따르되 답변 검수의 60초 한도를 넘기지 않습니다.
- 키 인증이나 요청 형식 오류는 자동 반복하지 않고 원인을 표시합니다.
- 검수 재시도는 이미 만든 같은 답변을 사용합니다. JEV 연결 실패 때문에 메인 AI에게 초안을 다시 만들게 하지 않습니다.
- 재시도에도 실패하면 받아둔 답변을 표시하고 검수 미완료로 기록합니다. 재작성 실패 시 최초 초안을 표시합니다. 첫 답변 자체가 없으면 검수를 시작하지 않습니다. 중단하면 받은 원문은 유지하고 늦게 온 수정 결과는 반영하지 않습니다.
- 확장의 18,000자 답변 제한을 없앴습니다. 긴 답변도 자르지 않고 검수하지만, 사용 중인 API의 출력·입력 한도는 그대로 적용됩니다.

자동 재시도가 발생하면 JEV 요청 횟수와 대기 시간이 추가될 수 있습니다.

### 마지막 오류 보내기

문제가 생기면 `설정 → 마지막 오류 → 오류 복사`를 눌러 전달해 주세요. `파일 저장`으로 텍스트 파일을 받을 수도 있습니다.

- 메인 AI 생성, JEV 검수, 수집·청소·번역·저장 등에서 관찰한 마지막 오류 1건만 기록합니다. 새 오류가 발생하면 이전 오류를 덮어씁니다.
- 정상 요청·성공·재시도 안내·30초 지연 안내는 기록하지 않습니다. JEV 30초 지연 토스트와 자동 재시도 기능은 그대로 작동합니다.
- 시각, 요청 경로 종류, 소요 시간, 글자 수, 오류 분류와 확인 가능한 코드 위치만 남깁니다. 채팅 원문·규칙 내용·인물명·API 키·원본 오류 문구는 남기지 않습니다.
- 같은 오류가 여러 함수를 거쳐 전달되어도 처음 실패한 단계와 소요 시간을 보존합니다. 확인 가능한 호출 위치, 오류 전달 경로, 하위 원인도 함께 남깁니다.
- 메인 AI 재작성 실패에는 생성 중 관찰한 요청 수와 최근 최대 6건의 HTTP 응답 코드·응답까지 걸린 시간을 함께 표시합니다. 동시 실행된 다른 요청이 섞일 수 있으므로 원인으로 단정하지 않으며, HTTP 200도 정상 답변을 보장하지 않습니다. 요청·응답 본문은 읽지 않습니다.
- 응답 없음·빈 응답·생성 중단·시간 초과·함수 호환 오류 등을 구분합니다. 알 수 없는 원인은 추측하지 않고 확인되지 않았다고 표시합니다. 기존 오류에는 새 세부 정보를 소급해서 붙일 수 없으므로 업데이트 후 다시 발생한 오류를 복사해 주세요.
- 마지막 오류는 새로고침해도 유지됩니다. 정상 작업이 성공해도 다음 오류나 직접 삭제 전까지 남습니다. 브라우저가 저장을 차단하면 현재 페이지에서만 확인할 수 있습니다.
- 이전 버전의 여러 기록은 업데이트 후 마지막 오류 1건만 남기고 정리합니다. 복사·파일 저장에도 이 오류 1건만 들어갑니다.
- `기록 지우기`는 진단 기록만 비웁니다. 수집한 규칙은 지우지 않습니다.
- 기록 자체는 추가 API 요청을 보내지 않습니다. 서버 내부 오류, 다른 확장의 오류, 100LOG가 로딩되기도 전에 발생한 오류까지 모두 수집할 수는 없습니다.

SillyTavern의 `확장 → 확장 설치`에 GitHub 저장소 주소를 입력합니다. ZIP 다운로드 주소를 입력하면 설치되지 않습니다.

수동 설치 시에는 다음 폴더 안에 8개 파일이 바로 보이도록 압축을 풉니다.

```text
data/<사용자>/extensions/third-party/100log/
```

## 업데이트

같은 GitHub 저장소의 파일을 새 버전으로 교체한 뒤 SillyTavern 확장 업데이트를 실행합니다.

기존 규칙·설정·JEV 키는 유지됩니다. 예전 메모리콩 기록은 각 채팅을 처음 열 때 해당 캐릭터 UUID 저장소로 이전됩니다. 설치 폴더 이름이 `memorybean`으로 남아 있어도 작동합니다.

## 알아두기

- 캐릭터별 1:1 채팅을 지원하며 그룹 채팅은 지원하지 않습니다.
- 공개 전 검수는 일반 생성·재생성·스와이프에 적용됩니다.
- 이어쓰기와 유저 역할 생성에는 공개 전 검수를 적용하지 않습니다.
- 활성 검수 규칙이 하나도 없으면 답변을 가로채지 않습니다.
- 첫 답변은 실리태번의 정상 생성 요청입니다. 수정 요청은 받은 답변과 확인된 충돌을 담은 별도 요청입니다.
- 다른 확장의 프롬프트를 읽거나 복원하지 않습니다.
- 실제 연결 상태는 SillyTavern 버전과 API 환경에 따라 달라질 수 있으므로 처음에는 짧은 채팅에서 확인하는 것을 권장합니다.
