# 🌱 메모리콩 0.2.0

SillyTavern RP 답변을 보여주기 전에 승인된 이야기 사실과 충돌하는지 확인하는 확장입니다.

## 설치

**SillyTavern의 `확장 설치` 입력창은 Git 저장소 URL을 받습니다. ZIP 링크를 입력하면 설치되지 않습니다.** 서버 플러그인은 필요하지 않습니다.

### GitHub에서 설치

1. 새 GitHub 저장소를 만들고, 이 ZIP을 **압축 해제**합니다. ZIP 파일 자체를 업로드하지 않습니다.
2. 압축을 풀어 나온 파일들을 **저장소 최상위**에 올립니다. GitHub 저장소를 열었을 때 `manifest.json`, `index.js`, `core.js`, `settings.html`, `style.css`가 바로 보여야 합니다. 별도 `memorybean/`이나 `server-plugin/` 폴더는 올리지 않습니다.
3. SillyTavern `확장 → 확장 설치`에 GitHub 저장소 주소(`https://github.com/사용자명/저장소명`)를 입력합니다.
4. 설치 후 `🌱 메모리콩`에서 TypeSafe AI API 키를 입력하고 `연결 확인`을 누릅니다.

이미 이전 파일을 GitHub에 올렸다면 저장소 최상위의 여섯 파일을 새 파일로 덮어쓴 뒤 SillyTavern에서 확장을 업데이트하고 페이지를 새로고침하세요. 이전 압축의 `server-plugin/`, `tests/`, `package.json`은 올리지 않아도 됩니다. 저장소 폴더 이름에 따라 설정 화면이 보이지 않던 문제는 0.1.1부터 설치된 파일의 위치를 직접 찾아 읽도록 수정했습니다.

### ZIP 수동 설치

SillyTavern의 `data/<사용자>/extensions/third-party/memorybean/` 폴더에 ZIP을 압축 해제합니다. 그 안에 `manifest.json`이 바로 있어야 합니다.

Jev 요청은 SillyTavern의 기본 채팅 API 경로로 먼저 보냅니다. 실리태번 서버가 Jev API로 요청을 전달하므로 별도 서버 플러그인이나 CORS 프록시 설정이 필요하지 않습니다. 이 경로가 없는 SillyTavern에서는 이전의 직접 연결 → 내장 CORS 프록시 순서로 다시 시도합니다. 마지막 경로까지 실패하고 `내장 프록시가 꺼져 있어요`가 표시될 때만 `SillyTavern/config.yaml`의 `enableCorsProxy: true`를 설정한 뒤 서버를 다시 시작하세요. 실리태번을 외부에 공개해 사용하는 경우에는 프록시 활성화 전에 실리태번 공식 보안 안내를 확인하세요.

키는 **현재 브라우저의 로컬 저장소**에 저장되므로 같은 SillyTavern 페이지를 열 수 있는 브라우저 스크립트에도 노출될 수 있습니다. 공유 기기에서는 사용 후 `키 삭제`를 누르세요. `401`이 나오면 키를 다시 확인하세요. 연결 실패 시 키 자체를 다른 사람에게 전달하지 마세요.

## 사용

1. 캐릭터와 채팅을 선택합니다. `마법봉 → 메모리콩`에서도 설정을 열 수 있습니다. 그룹 채팅은 첫 버전에서 지원하지 않습니다.
2. `이전 대화 전체 수집`을 한 번 누르면 **현재 열린 채팅**을 한 번에 최대 40개 메시지·18,000글자씩 차례로 읽으며 사실 후보를 모읍니다. 긴 단일 메시지도 여러 차례 나누어 끝까지 읽습니다. 긴 채팅은 메인 RP 모델을 여러 번 호출하므로 요금과 시간이 늘 수 있습니다. `수집 중단`을 누르면 현재 묶음을 끝낸 뒤 멈추며, 다시 누르면 이어서 읽습니다. 원문과 갱신 대상을 확인한 뒤 후보를 `승인`합니다.
3. 기존 사실이 바뀌었다면 후보의 **갱신 대상**을 선택해 승인하거나, 직접 추가 칸에서 갱신 대상을 골라 새 사실을 입력합니다. 이전 사실은 `지난 사실`에 남고 현재 사실만 검수합니다. AI가 인물·속성이 같은 앞선 사실을 발견하면 갱신 대상으로 제안하지만 자동 승인하지 않습니다. 장면이 바뀌면 `새 장면 시작` 버튼으로 임시 사실을 끌 수 있습니다.
4. 사실마다 `인물별 지식`을 열어 인물 이름과 `알고 있음` / `아직 모름`을 기록합니다. AI가 대화에서 명시된 지식 상태를 후보로 제안할 수 있습니다. 명시되지 않은 인물은 미확인 상태이며 비밀 누출 검수 대상으로 간주하지 않습니다.
5. `자동 검수 켜기`를 켭니다. 승인된 현재 사실이 없다면 일반 생성이 그대로 진행됩니다.
6. 사용자 메시지를 평소처럼 보냅니다. Jev가 먼저 초안에 관련된 사실을 뜻으로 고른 뒤 설정 충돌과 인물의 지식 누출을 확인합니다. 필요시 수정·재검수한 최종 답변만 표시합니다.

메모리콩이 활성화되면 일반 생성은 먼저 중단합니다. 검수 오류, API 오류, 수정 실패, 채팅 전환이 일어나면 숨은 답변은 표시하지 않고 설정창에 사유를 적습니다. 원할 때 자동 검수를 끄고 일반 생성 버튼을 눌러 다시 시도할 수 있습니다. 최대 한 번만 수정하므로 무한 생성하지 않습니다.

## 첫 버전의 범위와 확인할 점

- 원본 RP 모델을 `generateQuietPrompt()`로 호출합니다. 이 호출은 채팅의 캐릭터 정보를 유지하며 출력을 화면에 표시하지 않지만, 일반 생성과 프롬프트가 완전히 동일하지는 않을 수 있습니다. 메모리콩은 다른 확장의 설정이나 주입문을 읽거나 복원하지 않습니다. 다른 확장이 일반 생성에만 적용하는 주입은 숨은 생성에 적용되지 않을 수 있습니다.
- 자동 검수는 **일반 생성**만 적용합니다. 스와이프, 이어쓰기, 재생성, 그룹 채팅은 범위 밖입니다.
- 이전 대화 수집은 **현재 열린 채팅 파일의 메시지 전체**를 대상으로 합니다. 다른 채팅 파일들까지 자동으로 가져오는 기능은 아직 없습니다.
- 오래된 채팅에서 사실의 변경이나 인물이 아는 내용을 AI가 잘못 제안할 수 있습니다. 승인하기 전에 출처와 갱신 대상을 확인해야 합니다. `아직 모름`은 명시적으로 기록한 인물에게만 적용합니다.
- 뜻 기반 관련성 판단과 모순 판단을 나누므로 Jev 호출이 이전 버전보다 늘어납니다. 현재 사실은 최대 80개, 뜻으로 선택하는 관련 사실은 답변당 최대 16개이며, 긴 답변은 문단별로 나눠 검사합니다. 모든 오류를 찾거나 모든 사실의 현재성을 자동으로 보장하지는 않습니다.
- Jev는 사실과 문단 사이의 모순을 확률적으로 판정합니다. 세계관의 참거짓 전체를 증명하거나 모든 잘못을 보장해 잡아내지는 못합니다. 모델 오류로 승인된 사실과 충돌하는 답변이 남을 수 있습니다.
- SillyTavern 자체 서버 경로, 직접 호출의 CORS 허용 여부는 설치 후 `연결 확인`으로 검증해야 합니다.
- 실제 SillyTavern 및 TypeSafe API 계정에 연결한 통합 테스트는 이 패키지를 만드는 환경에서 실행하지 못했습니다. 설치 후 **짧은 테스트 채팅**으로 연결과 답변 표시 흐름을 확인해 주세요.
